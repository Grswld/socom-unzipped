# Web sprint 2 — "the SEAL in the world" — implementation plan

> Spec: `../specs/2026-09-28-web-sprint-2-the-seal-in-the-world-design.md` (its §4 is the batch, §8 the rulings
> W2.R1-R8). Written 2026-09-28 07:55Z against `agent/web-s1` at `e052c109` (`web/`: 531 tests in 45 files). Branch
> `agent/web-s2` in `C:\projects\wt-web-s2` (W2.R6). Status: **OPEN**. The Log at the foot is the live state, newest

**Goal:** the walk becomes the game's player as far as a TypeScript re-implementation carries it — the game's
third-person camera with a stand-in body in the frame, the game's speeds and ramp and fall, the game's reticle, a
hitscan shot that marks the wall — every number the game's own, cited; and the chrome the owner asked for.

**Architecture:** `@s2u/scene` gains `tuning.ts` (the SEAL's table off `READERC.ZAR`); `viewer` gains
`playerCamera.ts` (W2.1), the mover's throttle law, stances and fall in `walk.ts` (W2.2), `body.ts` (W2.3),
`reticle.ts` (W2.4), `fire.ts` (W2.5); `tools/extract-maps.ts` copies `READERC.ZAR` and `ZWEAPON.ZAR` beside the
maps. Nothing touches the recomp or the build; only W2.2 step 5 runs a game (PCSX2, under the lock).

## Global constraints

- **Worktrees.** Every task in an agent worktree cut from `agent/web-s2`: `bash scripts/agent_worktree.sh create
  web-s2-<task> agent/web-s2` from the main tree, then in it `cd web && npm install`, and the game data **copied**
  in (`robocopy C:\projects\socom_pc\web\public\maps <wt>\web\public\maps /E` and the same for
  `web\test-fixtures\RUN`; both git-ignored). **Never a junction:** the sprint's first removal (`wt-web-s2-chrome`,
  08:11Z) deleted through two data junctions the script does not know about and emptied the main tree's maps and
  fixtures (restored by `npm run extract-maps` at ~08:14Z; the Log). The controller merges
  back into `agent/web-s2` in `C:\projects\wt-web-s2` (skill `agent-worktree`; the merge happens in the sprint's
  worktree, never in the main tree: W2.R6). Never `C:\projects\socom_pc_web`, never `wt-web-s1` (stale).
- **Tests first.** Vitest, a failing test pasted RED then GREEN in the four-block report. Fixture-backed tests skip
  without game data, so every such test has a fixture-free twin on a synthetic input that runs on CI. `npm run
  typecheck && npm test && npm run build` from `web/` is every task's verification command; `npm run e2e` where the
  task says so. **Known on this host at the open:** `packages/archive/test/isoAssetSource.test.ts > names the maps

  session's trailer; no push from a worktree (the URL is dead); never `--no-verify`.
- **No game data in the tree.** `public/maps/`, `test-fixtures/` stay ignored; a test that needs bytes
  synthesises them.
- **Citations.** Code comments cite `docs/research/NN §n` (the repository's), `web/docs/research/NN`, the
  decompilation by `FUN_xxxxxxxx`, the script by name (`READERC.ZAR/motion.rdr`), and reCOM paths with line
