# Web sprint 1 — "the engine's world" — implementation plan

> Spec: `../specs/2026-09-28-web-sprint-1-the-engines-world-design.md` (its §4 is the batch, §8 the rulings
> W1.R1-R6). Written 2026-09-28 00:30Z against sprint-16's tip `2bcfbb7a` (`web/`: 311 tests in 29 files). Branch
> `agent/web-s1` in `C:\projects\wt-web-s1` (W1.R5). Status: **OPEN** 2026-09-28 (the cloud controller session, on the owner's word; the Log has
> the open). The Log at the foot is the live state, newest first.

**Goal:** the viewer holds the engine's world as the engine holds it — grid, regions, LOD fades, ground, disc spawns,
the detail pass — so a person walks Frostfire from A's spawn to B's at the SEAL's eye height over the game's floors.

**Architecture:** `@s2u/scene` gains the runtime structures (`grid.ts`, `probe.ts`, `aimaps.ts`); `viewer` gains the
behaviours that use them (`walk.ts`, the engine draw order in `world.ts`, `lodOpacity`, the detail pass); `archive`
gains the `_lib.rdr` manifest. Nothing touches the recomp, the build lock or the game.

## Global constraints

- **Worktrees.** Every task in an agent worktree cut from `agent/web-s1`: `bash scripts/agent_worktree.sh create
  web-s1-<task> agent/web-s1` from the main tree; the controller merges back into `agent/web-s1` (skill
  `agent-worktree`). Never `C:\projects\socom_pc_web` (stale, `feat/web-map-viewer`).
- **Tests first.** Vitest, a failing test pasted RED then GREEN in the four-block report. Fixture-backed tests
  (`test-fixtures/`, `public/maps/`) skip without game data, so every such test has a fixture-free twin on a
  synthetic input that runs on CI. `npm run typecheck && npm test && npm run build` from `web/` is the verification
  command of every task; `npm run e2e` where the task says so.
- **Commits.** `git commit -m "type(web/<pkg>): what and why" -- <paths>`; explicit pathspec; the session's trailer;
  no push from a worktree (the URL is dead); never `--no-verify`.
- **No game data in the tree.** `public/maps/`, `test-fixtures/` stay ignored; a test that needs a byte pattern
  synthesises it.
- **Citations.** Code comments cite `docs/research/NN §n` (the repository's) or `web/docs/research/NN` and reCOM
  paths with line numbers; a number reproduced from a note names the note.
- **Staffing.** Opus implementers (`.claude/agents/implementer.md`), a fresh reviewer per task
  (`.claude/agents/reviewer.md`); Fable for W1.2's region-writer question and W1.5's layout if the implementer
  stalls (W1.R6). Two agents at once at most; `npm test` is light, Playwright is not — one e2e at a time.
- **Host load.** No build lock is needed; still, `npm run e2e` and `tools/map-health.ts` open a browser over 22 maps
  and are run in a window the owner is not working in (memory: host load sensitivity).
- **Research numbers.** 75 is W1.5's (`web/docs/research/75-aimaps-mps.md`); any further note takes the next free
  number in `docs/research/` at the time (77 at the write).

## For a cloud agent

The owner is handing this plan to a cloud session (2026-09-28). What changes when the implementer is not on the
owner's machine:

- **Branch.** Start from `origin/agent/web-s1` (this plan's branch, cut from sprint-16's tip; it carries the 25
  web files `origin/main` lacks). Work on a branch off it, one PR per task back into `agent/web-s1`, or one PR for
  the batch if the owner prefers; never onto `main` or `sprint-16` directly. The worktree steps in the Global
  constraints are for the local controller and do not apply.
- **No game data.** The cloud tree has no `public/maps/`, no `test-fixtures/`: every fixture-backed test skips
  there. That is why each task's steps name a **synthetic twin** — write it first, it is the RED/GREEN the report
  pastes; the fixture assertion is still written, and the owner's local session runs it at merge. A PR whose only
  tests skip on CI is not done.

  marked "local" in the PR description with the exact command, and the local session runs them (Task 0's baseline,
  Task 2 Step 4, Task 3 Step 3, Task 4 Steps 3 and 6, Task 6 Step 3, Task 9 Step 1).
- **What the cloud agent can fully finish alone:** Task 1 (with the synthetic grid tests; the fixture numbers
  160/8/9 land as a skipping test), Task 3 Steps 1-2, Task 4 Steps 2 and 4 (synthetic), Task 5's decoder only against
  bytes the owner pastes or a dump the local session commits to the PR thread (the archive is not in the tree),
  Task 6 Step 1 (synthetic) and Step 2. Say in each PR which steps are done and which are handed back.
- **The references it needs are in the tree:** `research/recom/src/gamez/{zGrid,zRender,zVisual,zCamera}`,
  `docs/research/17`, `23`, `24`, `26`, `31`, `web/docs/research/71`, `72`, `web/packages/mesh/SEMANTICS.md`, the
  two earlier web specs. Nothing needs the recomp's build, `game/`, or `tools/`.
- **Report form** is the four blocks of `.claude/agents/implementer.md`: what changed (files, counts); RED and
  GREEN pasted; what is not done against this plan and why; the reviewer's command and the commit hash.
